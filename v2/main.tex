\begin{abstract}
% Written 2026-10-20 from the approved outline; replaces an earlier opening
% copied from DirectKV's abstract. Numbers that come from evaluation not yet
% run are \torun placeholders.
% Revised 2026-10-20 after Ben's review: higher register; the model-accuracy
% placeholder is gone (it belongs to s6); one \torun remains, the projected
% gain, whose value waits on the M22 discussion (1.37x today, 1.28x corrected).
% 2026-10-21 (Ben approved E1 contention term): 1.207x at ctx 14724 -> "21%";
% eta = 1.97 vs the aggregation bound 1 (s3.4, eq:eta).
The throughput of a disaggregated decode node is set by its batch size, and the
batch size by how much KV cache fits in the HBM that the model weights leave
free. For large models this is a handful of long-context requests, and most of
the GPU's compute sits idle. Memory beyond HBM is moving closer: coherent
CPU--GPU links such as NVLink-C2C reach hundreds of gigabytes at several
hundred GB/s, fast enough to deliver KV within a single decode step. A second
tier can serve decode in four ways: read the same batch over both tiers, read
every request's KV over the link, swap a share of every request's layers
through HBM, or split the batch by request. We show with one capacity model
that only the last two grow the batch, that both are bounded by the KV the
link can move within a step, and that they differ in what each moved byte
costs HBM. We present \sysname{}, which splits the batch \emph{by request}.
\emph{Residents} keep their KV in HBM; \emph{riders} keep theirs in the second
tier, occupy no HBM blocks, stream it layer by layer behind the batch's
compute, and write back only each step's new token. \sysname{} needs only the GPU's ordinary
asynchronous copies and the engine's existing attention kernel, so the same
engine runs over PCIe and over NVLink-C2C. The capacity model, from a one-time
profile and the measured step time, decides every step how many requests ride
and which ones. We implement \sysname{} in vLLM, decompose its overhead on an
A100, measure that copies into HBM slow decode in proportion to their traffic,
and validate the model against the measurements. Projected to a GH200 serving
Qwen2.5-72B at long context, riders raise decode throughput by 20\%, about
twice the gain per unit of link bandwidth that reading the same requests
faster could reach. In steady-state simulation they lead layer swapping by
3--7\% on mixed-context workloads, because each byte they move crosses HBM
once and travels the link's faster direction; when one request may also span
both tiers, they lead on every workload we test.
\end{abstract}
