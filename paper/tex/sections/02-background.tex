\subsection{System model: a disaggregated decode node}
\label{sec:background:pd}

\todo{WRITE THIS CAREFULLY --- it scopes every result in the paper.}

\todo{Prefill/decode disaggregation is the production default (DistServe,
Splitwise, Mooncake; vLLM's connector API exists for it). We target the
\emph{decode} node. Its input is a request whose KV already exists, delivered
over the transport from a prefill node.}

\todo{The consequence that matters: a host-tier request on a decode node need
never occupy an HBM block at all --- not even transiently for prefill. This is
what makes riders \emph{additive} rather than displacing
(\S\ref{sec:eval:capacity}). In a combined prefill+decode engine it is false,
and we measured the difference: with prefill resident, riders and residents
compete for the same headroom and the served total creeps toward the all-HBM
capacity from below without ever passing it.}

\todo{State the assumption plainly: KV arrives in host DDR. We implement the

away.}

\subsection{Threat to validity: what ``lossless'' means here}

\todo{bf16 attention reductions are batch-order dependent, so vanilla vLLM
itself produces different text for the same prompt at concurrency 1 versus 6.
Define the two-part gate used throughout: (a) serial comparison, batch of one
on both sides; (b) concurrent comparison restricted to prompts screened as
