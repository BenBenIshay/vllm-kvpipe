\section{Design}
\label{sec:design}

\subsection{Overview}
\label{sec:design:overview}

The system presents device memory (HBM) and host memory (DRAM) as one KV store.
Each request has a \emph{tier}. A \textbf{device-tier} request behaves exactly
as in stock vLLM: its KV blocks live in the paged device pool and attention
reads them there. A \textbf{host-tier} request holds \textbf{no blocks in the
device pool at all}; its KV lives in host DRAM, and each layer's bytes are
streamed across the interconnect just before that layer's attention consumes
them. Both tiers are served in one forward pass, so the weights are read once
per step however the batch is split.

\subsection{Where KV lives, and why the host has its own addresses}
\label{sec:design:spaces}

The host mirror is \textbf{not} indexed by device block id, and the rest of the
design rests on that.

The reason is a lifetime mismatch. The point of the host tier is that a
host-tier request's device blocks are released for others to use. Under vLLM's
allocator, releasing a block nulls the owner's block-table entry and returns the
id to a free list, from which it is promptly reissued. A mirror keyed by device
block id would therefore \emph{lose the read mapping} --- the request's block
table no longer records where its data was --- and \emph{alias}, because the
reissued id now denotes a different request's data.

Each \emph{(request, logical block)} is therefore given a host block id from a
private space, held until the request finishes. Device ids may churn freely
underneath. Growth needs no device allocation either: a new logical block gets a
fresh host block and its tokens arrive through the per-layer write path.

The price of a private space is that the active cohort's host ids are scattered
while the rolling region is a small dense array. Bridging them is the
\emph{compaction} of Figure~\ref{fig:compact}, run once per step.

\subsection{A decode step, end to end}
\label{sec:design:step}

Two granularities matter, and separating them is what keeps the per-layer work
small: \textbf{addresses} are fixed for the whole step, while slot
\textbf{contents} change every layer.

\begin{enumerate}
\item \textbf{Once per step --- compact} (Fig.~\ref{fig:compact}). Union the
      active cohort's host blocks, sort, map onto $[0,W)$, emit the compacted
      block table and the run list. Every layer reuses that block table.
\item \textbf{Per layer --- refresh.} Issue the runs into rolling slot
      $\ell \bmod k$. With $k>1$ this is issued ahead, so the transfer for layer
      $\ell{+}1$ overlaps the compute of layer $\ell$ (Fig.~\ref{fig:pipeline}).
\item \textbf{Per layer --- attend.} Device-tier rows read the paged pool with
      the ordinary block table; host-tier rows read slot $\ell \bmod k$ with the
      compacted block table. One forward pass, shared weights.
\item \textbf{Per layer --- write.} The token generated this step projects new
      $K,V$. For host-tier rows these go to the host mirror, which is
      authoritative, \emph{and} into the current slot so this step's own
      attention sees them.
\end{enumerate}

\paragraph{Why the device footprint is small.} A device-tier request's KV
occupies $L$ layers of blocks. A host-tier request occupies host blocks plus its
share of a rolling region that is $k$ slots deep \emph{regardless of $L$}, so
its device footprint is about $k/L$ of a resident request's --- roughly 6\% at
$k{=}4$, $L{=}64$. That ratio, not the interconnect, is what converts host DRAM
into device capacity.

\subsection{The life of a request}
\label{sec:design:lifecycle}

Figure~\ref{fig:lifecycle} shows the states and what triggers each transition.
Several transitions are driven by the \emph{worker} rather than the scheduler,
and that is not incidental: the scheduler cannot observe a host-side write, so
anything conditioned on KV having reached the host must wait for an
acknowledgement rather than assume.

Three scheduler behaviours must agree for a host-tier request to hold no device
blocks, and all three are necessary.

\emph{Admission without allocation.} The request is admitted with an empty block
list, its KV having been delivered into the host pool by the prefill transport
(\S\ref{sec:background:pd}), contingent on the worker's acknowledgement.

\emph{No prefill allocation.} Its prompt is marked already computed, so no
prefill is scheduled and nothing is allocated even transiently. The batch is
bounded by \emph{peak} device residency, so allocating during prefill and
reclaiming afterwards still pays the peak.

\emph{Queue bypass.} vLLM's waiting queue stops at the first request it cannot
allocate for. Since a host-tier request needs nothing, a block-starved request
ahead of it would otherwise block an admission that requires no resources.

\subsection{Placement}
\label{sec:design:placement}

Which requests should be host-tier? The intuitive answer is the long ones, since
KV grows with context. \textbf{Context length cannot discriminate}, by the
cancellation of \S\ref{sec:model}: moving a request of context $S$ to the host
frees $S\kappa$ bytes of device memory and costs $S\kappa$ bytes of interconnect
every subsequent step. Both scale identically, so ranking by context is
equivalent to ranking arbitrarily --- which \S\ref{sec:eval:ablation} confirms.

The discriminating signal is \textbf{temporal}. A request that is not currently
generating holds device memory while consuming no bandwidth at all, so the two
costs come apart exactly when a request is idle or near the end of its
generation. Placement scores requests on estimated remaining generation and time
since last activity, using only state the serving system already holds --- so it
needs no externally supplied service class. We keep the rule a transparent
threshold so that its behaviour can be explained.

\subsection{Admission}
\label{sec:design:admission}

Each host-tier request costs $S\kappa$ bytes of interconnect per step. Admission
bounds their sum by a budget: the step time times the achieved interconnect
bandwidth, less a margin.

Two properties of that budget matter more than its form. It is \textbf{measured,
not declared} --- the step time comes from steps carrying no host-tier traffic,
since a configured constant goes stale and the running latency average is
circular (host-tier traffic is exactly what it is being used to bound). And the
per-request cost is \textbf{derived from the model} ($L$, $n_{kv}$, $d_h$)
rather than configured, since a configured value that disagrees with the running
model is silently wrong.

A closed-loop guard sits behind the budget: an exponentially weighted average of
observed step time, compared against the latency objective with hysteresis,
gates new admissions when the system is already over. The budget bounds what
should fit; the guard responds to what did.

\subsection{Migration}
\label{sec:design:migration}

Placement must be revisable, so requests move between tiers with hysteresis on
both edges and a cooldown bounding thrash.

The gate on those moves is measured rather than predicted. A cost model asking
whether a request's transfer fits the remaining budget is \emph{necessary but
not sufficient}: the budget accounts for transfer bytes, while the host path
also carries a per-step cost independent of how many bytes move
(\S\ref{sec:impl}). A gate that sees only bytes cannot see that cost, and
widening the margin does not repair the omission.

A demotion is therefore a \textbf{probe}. The controller records the best recent
steady-state latency, performs the move, waits a settling period, and compares;
if latency regressed beyond a margin the request is promoted back and the
cooldown grows exponentially. Two details are forced by the noise floor: the
baseline must be a recent \emph{minimum} rather than the instantaneous average,
which would otherwise absorb startup transients, and the loop needs a warmup so
the first probe has a steady state to compare against.

The probe is single-variable attribution in a system where requests arrive and
depart during the settling window, so its verdict is noisy, and the margin and
backoff bound the cost of a wrong one. Its value is that it is \emph{correct in
direction} where a byte-counting model is not: \S\ref{sec:eval:ablation} reports
it reaching opposite verdicts on the two interconnects, which is what a
placement policy should do when the hardware changes under it.
