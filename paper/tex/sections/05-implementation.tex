\subsection{Reclaim}
\todo{The worker acknowledges the seed and the scheduler reclaims only on that
ack -- the scheduler cannot know the device-to-host copy happened, and guessing
loses history on a pool-setup failure. Promotion had to be repaired alongside:
block accounting is LENGTH-based, so an in-place null counts as present, and
the phase-2 "blocks cover the whole sequence" gate would have passed on an
all-null table and served garbage.}

\subsection{What the transfer path cost us, and why}
\todo{WORTH A FULL SUBSECTION -- it generalises beyond this system.}
\todo{(1) LAYOUT. A per-layer $[2,H,bs,\ldots]$ mirror makes a run of blocks two
chunks strided by a whole K/V plane, so no pinned DMA is possible and every
layer pays a CPU staging gather: 22\,ms/layer, 72\% of wall. Block-major with
SPLIT K and V makes a run one contiguous byte range on both sides and the DMA
engine does the compaction. CPU gather 10096\,ms $\to$ 39\,ms. On a fast
interconnect this defect would have been INVISIBLE and we would have concluded
that C2C does not help while measuring our own memcpy.}
\todo{(2) LOOP-INVARIANT WORK. Four sites, one species: work computed per layer
that is fixed once the step's schedule is known (a device reduction plus
\texttt{.item()} inside a guard meant to SKIP work; scatter indices; sequence
maxima; a masked clone). Fixed cost 37.02 $\to$ 12.29\,ms, headline
$-11.3\% \to -2.3\%$, controls reproducing to 0.1 tok/s over five runs, no
numerics touched.}
\todo{(3) WHAT REMAINS IS A FLOOR, NOT A BUG. An operator trace shows
\texttt{cudaStreamSynchronize} gone from the table entirely and no dominant
remaining term: ~640 extra kernel launches per step (10 operations $\times$ 64
layers), 0.19\,ms per layer. Machine-independent, so it does not corrupt the
C2C measurement. Getting past it needs batching ACROSS layers -- the k-window
slots already exist for it -- which is a design change, not a fix.}
\todo{(4) METHOD. Two rounds of aggregate per-phase timers produced two wrong
diagnoses, because a timer around async GPU work charges waiting-for-the-GPU to
whoever holds it. An operator-level diff (0-rider against 1-rider on identical
prompts) found all four sites. Related earlier bug: a
\texttt{synchronize()} inside the timing wrapper made async double-buffering
impossible BY CONSTRUCTION, so it "showed" the optimisation to be useless.}
