\section{Work in Progress: Implementation Gaps}\label{sec:wip}

\textcolor{red}{Note to the authors, to be removed before submission. Each item
is a place where the code does not yet do what the body describes.}

\begin{enumerate}\itemsep2pt
\item \gap{Admission (\cref{sec:admission}, \cref{alg:admit}): the runtime
  controller does not yet evaluate \cref{eq:decision}. It enforces a byte
  budget of $T_0\Xlink$, so it stops at the last rider that hides
  (\texttt{hide\_budget\_headroom\_bytes}) instead of applying the
  throughput test at line~\ref{alg:knee}; it computes neither the gate nor
  $\rmin$ (line~\ref{alg:commit}), and relies on the probe to undo moves that do not
  pay. To add: read $F$, $c$ and $\delta$ from the profile at
  line~\ref{alg:model} and replace the byte budget with $\Theta$ (the
  marginal hook \texttt{\_marginal\_ok} is where it goes). Every projection in
  the body uses the throughput test.}
\item \gap{Admission ordering: candidates are taken in arrival order, and
  demotion picks by a temporal score (idle time, remaining generation), which
  is off by default. Neither orders by context (lines~\ref{alg:res},
  \ref{alg:order} and~\ref{alg:migr}). Demotion is triggered by inter-token
  latency watermarks rather than by a full HBM with requests waiting.}
\item \gap{Model inputs: $\Xlink$ is the configured link bandwidth, not a
  measured one; the resident count is a configured cap rather than derived
  from $\Mkv$; and $T_0$ is not yet measured while serving
  (\cref{sec:opoint}).}
\item \gap{Host pool (\cref{sec:impl}): extents are sized for the model's
  maximum length, not for each request's prompt plus its token limit; a
  per-request size needs the request's sampling parameters at admission, which
  the pool does not see.}
\item \gap{Defaults (\cref{sec:switches}): the copy-stream overlap is on in
  every measured run but is still opt-in in the engine
  (\texttt{RUNGD\_ASYNC} defaults to 0); it should default to on.}
\end{enumerate}
