\subsection{What Each Building Block Is Worth}\label{sec:ablation}

\paragraph{Setup.} All ablations run on one A100-80 (PCIe) serving
Qwen2.5-32B-Instruct in fp16 ($L{=}64$ layers, KV blocks of 16 tokens, a rolling window
of $k{=}4$ layer-slots). Block size 16 is the engine default. The prefetch
runs one layer ahead, so $k{=}2$ is the minimum; $k{=}4$ is the default, and
sweeps at $k{=}2$ and $k{=}8$ change the step time by under 1\,ms at every
rider count, including counts past the knee. Each extra slot costs only $1/L$ of a rider's KV in HBM. The node is a decode node with the handover emulated:
each rider's KV is delivered into host DDR through the KV connector before the
rider is admitted, as it would arrive from a prefill node. Every step of every
retained measurement is checked to be pure decode --- no prefill tokens, no
waiting requests, a constant running set --- and a rider count with any impure
step is discarded, not corrected. Each rider count is run five times.

\paragraph{Method.} A sweep holds a fixed cohort of residents and adds riders
one count at a time; $\Delta T(r)$ is the step time with $r$ riders minus the
step time with none. We fit $\Delta T = F + c\,r$ (\S\ref{sec:model}) by least
squares over the rider counts whose transfer time is at most a third of the
step, so that the fit stays below the knee: a fit across the knee raises the
slope and lowers the intercept together. An \emph{ablation arm} removes one
mechanism and keeps every other launch, hook, event and stream ordering, so the
difference between arms is that mechanism and nothing else. Each arm is a
runtime switch of the same binary, not a separate build; the switches are
listed in \cref{sec:switches}. The two arms of a pair run in the same job
wherever the figure says so.
\emph{Run-to-run noise.} Repeating a configuration within one job moves $c$ by
0.03\,ms and $F$ by 0.04\,ms. Repeating it in a different job can move $F$ by up
to 0.5\,ms, because the job's starting state differs. We therefore plot repeats
as separate series, compare arms within one job where possible, and treat any
difference in $F$ below 0.5\,ms as noise.

\paragraph{Rolling layer cache: the transfer is hidden, not merely
shortened.} \Cref{fig:abl-law}a is a sanity check of the harness rather than a
claim: it removes the copy stream's overlap by serialising it with compute, the
baseline any prefetching design improves on. A rider then costs 7.20\,ms of step time against 6.17\,ms of
link time: the transfer is fully exposed, plus its bookkeeping. With the
overlap, the same sweep costs 0.93\,ms per rider, and that slope is an upper
bound, since it includes counts approaching the knee. \Cref{fig:abl-law}b says
what is left below the knee, at light load. Removing the bytes while keeping
every launch moves $c$ from 0.522 to 0.532\,ms, inside the noise: with the link
busy for under a fifth of the step, the rider's transfer costs nothing, and $c$
is the host work around it.

\paragraph{Landing the bytes in HBM is not free.} At higher load the bytes
cost something. At context 1024 with the link busy for up to 98\% of the step,
real bytes raise $c$ from 0.76 to 1.59\,ms over the same sweep with the bytes
removed, two arms interleaved in one job; at contexts 256 and 512 the
increase is 0.29 and 0.53\,ms, in proportion to the bytes. The transfer still
hides; what it takes is HBM bandwidth. \Cref{fig:abl-contention} isolates
this outside the engine: the decode step's weight GEMMs, timed while a second
stream copies into HBM at a controlled rate, slow down linearly in the copy's
traffic, by $\kappa = 1.06$ times its share of HBM peak bandwidth. This is the
contention term of \cref{eq:cS}. Two terms of the step's structure add to it
here: the first layer of each rider is copied on the compute stream, and the
deferred write-back grows with real bytes. Together the three account for
0.71 of the 0.83\,ms. Copies from the host over PCIe cost about four times
more per byte than device copies, so the A100 link is a pessimistic case; the
projection uses $\kappa = 1.06$, consistent with the up to 10\% that DAK
reports for background copies on GH200 (\S\ref{sec:profile}).

\paragraph{The deferred write-back is a fixed cost, and halves it.}
\Cref{fig:abl-law}c replaces the deferred write-back with a blocking
device-to-host copy per layer. The two lines are parallel ($c$ 0.49 and
0.52\,ms) and their intercepts differ by 6.8\,ms: the write path is paid once per
step regardless of rider count, and deferring it takes $F$ from 12.63 to
5.80\,ms. Each blocking copy took 71\,\textmu s to move one token's $K,V$ for
one layer, a few kilobytes that the link carries in about 0.16\,\textmu s. The
cost was the synchronisation, not the transfer.

\paragraph{Step-invariant addressing removes the per-block term.}
\Cref{fig:abl-addr}a times the host work of building the step's rider block
table. Built one entry per rider block, it costs 2.6\,\textmu s per block per
step, so one rider at context 14\,724 costs 2.38\,ms, and the step grows by the
same 2.38\,ms: the build sits wholly on the critical path. Built one slice per
rider, the table costs 0.03--0.045\,ms per step at every context, and
quadrupling the block size --- a $4\times$ change in block count at the same
riders --- moves it by 2--6\%. \Cref{fig:abl-addr}b carries this to the
per-rider cost $c$, measured with the bytes removed so that no context is past
the knee. With one slice per rider, $c = 0.50 + 0.21$\,ms per thousand tokens.
The slope is not addressing: a resident adds 0.20\,ms per thousand tokens to
$T_0$, so the rider pays for its attention what a resident pays, and the
intercept is the mechanism, $c_m$ of \cref{eq:cS}. With the per-block table the
slope is 0.37\,ms per thousand, $1.8\times$ steeper, and at the target context
$c$ is 6.0\,ms against 3.5--3.75\,ms.

\paragraph{Two arms not plotted.} The host layout is what lets each contiguous
run be one copy: with $K$ and $V$ interleaved, every run became a host-side
gather, 10{,}096\,ms against 39\,ms in one benchmark. And in today's two-call
attention, masking each rider row of the first call to a single key was worth
22\% of wall time on A100.

\paragraph{What fusing the attention calls could buy.} \Cref{fig:abl-fusion}
removes the second attention call's kernel, then the whole call. The call costs
1.21\,ms of the 3.36\,ms fixed cost, almost all of it the kernel and its launches
(1.16\,ms), and 0.13\,ms per rider for gathering and scattering rider rows. A
fused kernel removes the gather and scatter outright; it removes at most the
$F$ share, since it still performs the attention arithmetic. Fusion's value is
therefore a range, not a number. \planned{fusion is not implemented; its row in
\cref{tab:ladder} is a projection from these ablation arms.}

\paragraph{The ladder.} \Cref{tab:ladder} carries each block to the target
through the capacity model. As first built, a rider cost more than a token is
worth, so the gate failed and no rider count could pay at any bandwidth.
Addressing passed the gate, but with the fixed cost still at 13.4\,ms
break-even needed three riders, and the knee admits two. The deferred write-back is what made
them pay. Admission (\cref{alg:admit}) turns any failing state into $1.00\times$
rather than a loss, by admitting no riders.
