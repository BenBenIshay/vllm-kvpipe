\begin{abstract}
A decode server's batch is capped by device memory, not arithmetic: KV cache
exhausts HBM long before the arithmetic units are busy, so the GPU runs at
single-digit utilization while turning requests away. Coherent CPU--GPU
interconnects make host DRAM fast enough to hold the KV of an \emph{actively
decoding} request, but existing systems vary how much KV sits on the host and
never \emph{whose} --- they place none, or a uniform fraction of every request.

We present a heterogeneous KV memory that manages HBM and host DRAM as one
store and assigns each request a tier. A host-tier request holds \emph{no}
device blocks: its KV is streamed layer by layer into a rolling buffer whose
footprint is $k/L$ of a resident request's, and both tiers are served in one
forward pass, so weights are read once however the batch is split.

We derive when a second tier pays. The capacity multiplier is one plus the
interconnect-to-HBM bandwidth ratio times the ratio of device memory to what the
weights leave free, so --- counter to intuition --- context length cancels and
the value tracks how much memory the weights consumed. But capacity is not throughput. Charging the fixed per-step cost of
using a host path at all gives a \textbf{second gate}, and it is the binding
one: at the cost we measure, \emph{every} configuration the multiplier likes
still loses. We therefore report what that cost would have to be, which turns
the question into one falsifiable number per configuration.

We implement this in vLLM and measure it on PCIe --- the regime the model calls
unfavourable, and where it is duly negative. Host-tier requests are
\emph{additive}, raising peak concurrency from 8 to 48 against a fixed pool ---
at $0.53\times$ the throughput, so this is a mechanism check and not a result;
overlap efficiency is $0.62$ and the fixed cost $12.3$\,ms. Coherent-interconnect
results are pending and stated throughout as predictions.
\end{abstract}
